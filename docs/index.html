Agent Pair Scaping

A bench inspired by Max's RuneBench and rs-sdk.

The task

2 agents on new characters must team up to kill as many unique enemies as they can within 15 minutes. Tougher enemies are worth more.

score = Σ ln(1 + level)

A level-2 Goblin is worth 1.10 and a level-5 Goblin 1.79, the stronger killed later adds the difference. Scoring by natural log rewards exploration: ten different easy monsters beat one hard one. Repeat kills are worth zero.

Notes

  • A kill ledger records every NPC death, credited to the player who did the most damage (the game's own loot rule). Agents are not told when they've scored. Keeping track of what the team has killed is part of the task.
  • The game runs at 8× speed with the server's 25× XP rate. Agents aren't told the XP rate.
  • Harness: each agent is an OpenCode 1.19.3 session using a model through OpenRouter. It plays by writing TypeScript for rs-sdk's execute_code tool and reads the world state that comes back.

Limitations

  • Small samples. The screening runs are one run per model, and in the main results three runs of the same team ranged from 86 to 113 (Sol), 19 to 38 (DeepSeek), 12 to 24 (Qwen) and 9 to 18 (Haiku).
  • One harness. Every model played through OpenCode with the same prompt and tools. Some models may do much better with a harness built for them.
  • The screening runs aren't directly comparable with the main results. The patches and prompt changed in between.
  • Cost depends on routing. OpenRouter picks a provider per request, and prices differ between them.
  • Wall-clock time. The 15 minutes are real time, so a slow provider costs a model score as well as money.

Changes from rs-sdk and rs-bench

The main results (r047 onward) have all of these. The screening runs in the appendix had only the dialogue text and the kill ledger.

  • Level-up messages no longer block the agent. In stock rs-sdk the "Congratulations" box stops your attack until something clicks continue, and at 25× XP that happens every kill or two. Now the level goes to the chat box instead.
  • The Al Kharid toll gate is free and needs no dialogue. The border guard conversation stalled agents for minutes without testing anything the benchmark measures.
  • Private messages work. The engine silently dropped PMs unless the friend server was running.
  • The game tool no longer dies. An un-awaited sdk.say() at the end of a call could crash the MCP server, leaving that agent with no game for the rest of the run.
  • The world state shows dialogue text, not just the options (from r019).
  • A kill ledger records every NPC death with its level, for scoring.
  • The prompt's scoring examples are bare levels (from r047). Earlier prompts gave examples by name (Chicken, Goblin, Guard, Lesser demon), and agents treated them as a to-do list: several hunted for a guard in Lumbridge Castle that doesn't exist, and a few became fixated on lesser demons.

Appendix: screening sixteen models

Before the main runs, a first pass gave every model one run, to see which could play at all. These runs predate most of the changes.

Outliers

In reruns, HY4 Preview scored 49.6 in r034, then 11.7 and 14.9 in r045 and r046. GPT-6 Luna went from 31.3 to 18.9.

The changes helped Sol far more than DeepSeek: Sol's mean in the main runs is 27% above its screening run (76.8), DeepSeek's only 8% above its screening score (29.0).
